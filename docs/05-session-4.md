# 4주차: 안전한 공유와 개선

## 이번 주 목표

결과물을 다른 사람에게 설명하고, 공개 가능 여부를 판단하며, 다음 30일 운영 계획을 만듭니다.

## 실습 1: 완료 조건 검토

`PROJECT.md`의 완료 조건을 하나씩 확인합니다.

| 완료 조건 | 상태 | 근거 | 남은 문제 |
|---|---|---|---|
| 예시 입력을 처리한다 | 충족/부분/미충족 | 파일·화면·테스트 링크 |  |

모든 조건을 억지로 충족 처리하지 않습니다. 부분 완료와 알려진 한계를 정확히 적는 것이 더 중요합니다.

## 실습 2: 최종 검증

- [ ] 대표적인 정상 입력을 확인했다.
- [ ] 비어 있거나 잘못된 입력을 확인했다.
- [ ] 연구·지식 결과는 원출처와 대조했다.
- [ ] 자동 생성된 링크와 인용이 실제로 존재하는지 확인했다.
- [ ] 다른 사람이 README만 보고 핵심 결과를 확인했다.
- [ ] 알려진 오류와 한계를 기록했다.

## 실습 3: 공개 전 보안 점검

[보안과 공개 기준](07-security-and-sharing.md)을 사용합니다.

- [ ] 비밀번호, 토큰, API 키가 없다.
- [ ] 이름, 주소, 연락처 등 개인정보가 없다.
- [ ] 타인의 자료를 허가 없이 포함하지 않았다.
- [ ] 학교·회사·연구기관의 비공개 자료가 없다.
- [ ] 파일 속성과 이미지에 불필요한 정보가 없다.
- [ ] 공개 저장소의 과거 커밋에도 비밀정보가 없다.
- [ ] 공개 범위를 참가자가 직접 선택했다.

한 항목이라도 확실하지 않으면 공개하지 않고 수업 안에서만 시연합니다.

## 실습 4: 3분 시연

[최종 시연 템플릿](../templates/final-showcase.md)을 사용합니다.

1. 어떤 문제가 있었는가?
2. 무엇을 만들었는가?
3. AI에는 무엇을 맡겼고 사람은 무엇을 판단했는가?
4. 결과가 맞는지 어떻게 확인했는가?
5. 시간·비용·판단이 어떻게 달라졌는가?
6. 아직 해결하지 못한 것은 무엇인가?

## 실습 5: 멀티에이전트 맛보기

멀티에이전트는 여러 에이전트가 동시에 파일을 고치는 기능으로 시작하지 않습니다. 우선 읽기와 검토 작업을 분리합니다.

예시 역할:

- 계획 검토자: 목표와 누락된 조건 확인
- 검증 담당자: 테스트와 출처 확인
- 보안 검토자: 공개 위험 확인

각 역할은 같은 결과물을 다른 기준으로 읽고 짧은 보고서를 반환합니다. 최종 판단과 파일 변경은 참가자가 승인합니다.

## 실습 6: 30일 계획

다음 달에는 프로젝트를 무작정 크게 만들지 않습니다.

- 유지할 산출물 루프 1개
- 자동화할 반복 작업 1개
- 제거할 불필요한 도구 또는 구독 1개
- 보완할 검증 절차 1개
- 공개하거나 설명할 결과물 1개
- 다음 점검일 1개

## 최종 제출물

- 최종 결과물
- 최신 `PROJECT.md`
- 검증 기록
- README
- 보안 점검표
- 3분 시연 자료
- 최종 자기진단
- 30일 계획

## 수료 체크리스트

- [ ] 결과물을 직접 보여 줄 수 있다.
- [ ] 문제와 완료 조건을 설명할 수 있다.
- [ ] AI가 한 일과 내가 판단한 일을 구분할 수 있다.
- [ ] 검증 근거를 제시할 수 있다.
- [ ] 공개 위험을 확인했다.
- [ ] 다른 사람이 재현할 수 있다.
- [ ] 다음 개선 행동이 정해졌다.
