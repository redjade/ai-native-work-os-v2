## 작업 방식

- 파일을 수정하기 전에 관련 자료와 현재 상태를 확인한다.
- 복잡하거나 여러 파일을 바꾸는 작업은 계획을 먼저 제시한다.
- 한 번에 하나의 검증 가능한 변화만 만든다.
- 사용자가 만든 기존 변경을 임의로 삭제하거나 되돌리지 않는다.
- 불확실한 내용은 사실처럼 작성하지 않고 확인 필요로 표시한다.

## 보안

- 비밀번호, API 키, 토큰과 개인정보를 파일이나 로그에 기록하지 않는다.
- 프로젝트 폴더 밖의 자료에 접근하기 전에 승인을 요청한다.
- 외부 업로드, 공개, 메시지 전송, 결제는 명시적 승인 없이 수행하지 않는다.
- 삭제나 대규모 변경 전에 영향과 복구 방법을 설명한다.
