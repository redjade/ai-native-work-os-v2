## 색의 뜻

열 그림에서 색을 같은 뜻으로 씁니다. **한 색이 두 가지 뜻을 갖지 않게 하는 것이 이 규약의 목적입니다.**

| 색 | 클래스 | 뜻 |
|---|---|---|
| 파란색 | `blue` | 도구·에이전트가 하는 일, 지금 보이는 것 |
| 회색 | `gray` | 사라지거나 보이지 않는 것, 작동하지 않는 예 |
| 노란색 | `amber` | 사람이 판단하는 자리, 놓치면 곤란한 요점 |
| 흰색 | `bx` | 묶음 상자, 중립 정보 |

색만으로 뜻을 전달하지 않습니다. 상자 안의 글자만 읽어도 같은 내용을 알 수 있어야 합니다.

## 수정할 때

- 텍스트 편집기나 AI 도구로 직접 고칩니다. 그림 편집 프로그램이 필요하지 않습니다.
- 가로는 720으로 맞춥니다. 문서 폭에 맞게 축소되어 보입니다.
- 글자 크기는 14px(제목)과 12px(부제) 두 가지만 씁니다.
- 배경은 흰색으로 고정했습니다. GitHub의 밝은 화면과 어두운 화면 어디서나 글자가 읽히게 하려는 선택입니다. 어두운 화면에서는 밝은 카드로 보입니다.
- 글꼴은 특정 제품을 지정하지 않고 시스템 글꼴을 사용합니다. 다른 사람 화면에서 깨지지 않게 하려는 것입니다.
- 라벨을 길게 늘이면 상자를 넘칩니다. 한글은 14px에서 한 글자당 약 15px, 12px에서 약 13px로 계산해 상자 너비 안에 들어오는지 확인합니다.
- `<title>`과 `<desc>`를 반드시 넣습니다. 그림을 볼 수 없는 사람에게 읽히는 내용입니다.
- 새 그림을 추가하면 이 표에 한 줄 넣습니다.

## 어떤 것을 그림으로 만드나

산문으로 설명하기 어려운 **구조**, **흐름**, **비교**, **경계**만 그립니다. 목록으로 충분한 것(체크리스트, 준비물)과 한 번 보고 넘길 것은 그리지 않습니다. 장식용 그림은 관리 부담만 늘고, 문서를 고칠 때 함께 낡습니다.

그림 수를 미리 정해 두지는 않았습니다. 위 기준을 통과하고 여러 번 다시 참조되는 것만 추가합니다. 제작·검수 기준과 그리지 않기로 판단한 항목은 운영 저장소의 다이어그램 가이드에 기록되어 있습니다.
