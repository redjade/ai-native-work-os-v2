## 실습 5: 멀티에이전트 맛보기

> **무엇을** 내 결과물을 서로 다른 기준으로 읽는 검토자 3명을 순서대로 돌리고, 내가 종합해 결정합니다.
> **왜** 만든 사람은 자기 결과물의 문제를 잘 못 봅니다. 관점을 바꿔 읽어야 보입니다.
> **나에게 무슨 의미** 혼자 작업하면서도 여러 사람에게 검토받는 효과를 얻습니다.

멀티에이전트는 여러 에이전트가 **동시에 파일을 고치는 것**으로 시작하지 않습니다. 이번 주에는 **읽기만 하는 검토자 3명 + 쓰기는 주 도구 하나 + 결정은 사람**으로 시작합니다.

### 0단계 — 감 잡기 (2분, 내 프로젝트 밖에서)

내 결과물로 바로 시작하지 않습니다. 먼저 **아무 이해관계 없는 주제**로 한 번 돌려 보고 "일을 나눠 시킨다"가 어떤 모양인지만 봅니다.

새 대화를 하나 열고 그대로 붙여 넣습니다.

```text
자. 너는 대장 에이전트야. 이제 네가 할 일은 내가 하는 말을 잘 듣고
다른 에이전트에게 일을 시키는 거야.
할 일을 말해 줄 테니 최대 3개의 에이전트에게 일을 분배해서 진행시켜.
자, 할 일을 나열하겠다.
짜파게티를 주제로 하는 시를 짓고, 이것을 다른 에이전트가 검토하게 해라.
그리고 목살 굽는 레시피를 만들고 이를 다른 에이전트가 검토하게 하라.
```

시와 레시피가 목적이 아닙니다. 볼 것은 세 가지입니다.

- **만든 쪽과 검토한 쪽이 다르다** — 왜 검토를 따로 두는지 한 번에 이해됩니다.
- **일이 쪼개져 나뉜다** — "한 대화에 다 시키기"와 모양이 다릅니다.
- **중간이 잘 안 보인다** — 누가 무엇을 왜 그렇게 판단했는지는 남지 않고 결과만 옵니다.

세 번째가 이 워밍업의 진짜 교훈입니다. 시와 레시피는 틀려도 아무 일이 안 생기지만, **내 결과물에서는 그 판단 하나하나가 중요합니다.** 그래서 아래부터는 지휘자를 에이전트가 아니라 나로 바꿉니다.

> 짜파게티·목살 자리에는 아무 주제나 넣어도 됩니다. 다만 **내 프로젝트 폴더 밖에서** 하고, 결과물은 저장하지 않습니다.
> 쓰는 도구에 하위 에이전트 기능이 없으면 한 대화 안에서 역할을 나눠 흉내 내기도 합니다. 그래도 이 단계의 목적은 달성됩니다.

### 흐름 — 지휘자는 나

```text
[나] 검토 범위 승인
  → [역할 1] 계획 검토자 → 보고서
  → [역할 2] 검증 담당자 → 보고서
  → [역할 3] 보안 검토자 → 보고서
  → [나] 세 보고를 종합해 무엇을 고칠지 결정   ← 핵심 단계
  → [주 도구] 승인한 것만 수정
  → [나] 변경 확인 → 커밋
```

에이전트가 다른 에이전트를 알아서 호출하게 하지 않습니다. **한 명씩 순서대로** 돌리고, 종합은 내가 합니다.

### 세 역할

| 역할 | 무엇을 보나 |
|---|---|
| 계획 검토자 | `PROJECT.md`의 완료 조건을 정말 충족했나, 빠진 조건은 무엇인가 |
| 검증 담당자 | 주장·수치에 근거가 있나, 지어낸 인용은 없나, 예시·오류 입력은 통하나 |
| 보안 검토자 | 개인정보·비밀정보·타인 자료가 섞이지 않았나 |

성격 설정("냉철한 전문가입니다")은 넣지 않습니다. 검토 품질은 성격이 아니라 **기준·금지사항·보고 형식**에서 나옵니다.

### 진행 방법

[검토 역할 템플릿](../templates/review-roles.md)을 사용합니다.

1. 역할 하나마다 **새 대화(세션)를 엽니다.** 같은 대화에서 역할만 바꾸면 앞의 결론에 물들어 새 문제를 못 찾습니다.
2. 템플릿에서 해당 역할 블록 + 공통 규칙을 붙여 넣고, 검토할 파일 경로를 채웁니다.
3. 공통 규칙에는 이것이 반드시 들어갑니다 — **"파일을 수정하지 마세요. 확실하지 않은 것은 추측하지 말고 질문으로 남겨 주세요."**
4. 받은 보고서를 `logs/review-<역할>-<날짜>.md`로 저장합니다.
5. 세 보고서를 다 받은 뒤, `logs/review-decision-<날짜>.md`에 **무엇을 받아들이고 무엇을 넘길지, 그 이유**를 직접 적습니다. 이 파일은 AI에게 맡기지 않습니다.

### 내가 결정해야 하는 4개 지점

| 지점 | 내가 하는 일 |
|---|---|
| 검토 시작 전 | 어떤 파일을 어떤 기준으로 볼지 확정 |
| 보고가 엇갈릴 때 | 어느 지적을 받아들일지 판단 (양쪽 다 맞을 수도 있음) |
| 파일 수정 직전 | 고칠 목록을 승인. 승인 안 한 것은 고치지 않음 |
| 공개 직전 | 보안 점검 통과 확인 |

수정과 공개는 되돌리기 가장 어려운 순간이라 사람이 반드시 통과 지점을 지킵니다.

### 확인

- [ ] 이해관계 없는 주제로 위임을 한 번 돌려 봤다(0단계).
- [ ] 검토자가 파일을 수정하지 않았다.
- [ ] 역할마다 새 대화에서 진행했다.
- [ ] 세 보고서가 서로 다른 관점을 담고 있다.
- [ ] 엇갈린 지적을 내가 판단했다.
- [ ] 결정과 이유를 파일로 남겼다.

더 자세한 방법(도구별 진행, 읽기 전용 설정, 흔한 실패)은 [멀티에이전트 기초](13-multi-agent-basics.md)에 있습니다.
