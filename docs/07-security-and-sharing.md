# 보안과 공개 기준

## 기본 원칙

1. 비공개로 시작하고 필요한 것만 공개합니다.
2. AI에 제공할 수 있는 정보와 저장소에 올릴 수 있는 정보는 별도로 판단합니다.
3. 비밀정보는 나중에 지우는 것이 아니라 처음부터 입력하지 않습니다.
4. AI가 제안한 명령과 파일 변경은 사람이 확인한 뒤 승인합니다.
5. 공개가 학습의 필수 조건은 아닙니다.

## 절대 입력하거나 저장하지 않을 정보

- 비밀번호와 로그인 복구 코드
- API 키, 접근 토큰, 인증서와 개인 키
- 주민등록번호, 여권번호, 금융정보
- 집 주소, 개인 전화번호, 실시간 위치
- 타인의 개인정보와 비공개 대화
- 학교·회사·연구기관이 외부 제공을 금지한 자료
- 시험 답안, 환자 정보, 상담 기록 등 고위험 자료

## 미성년 참가자 추가 기준

- 보호자와 공개 범위를 함께 확인합니다.
- 학교명, 학년·반, 얼굴 사진, 주소와 동선을 공개하지 않습니다.
- 다른 학생의 이름과 작업물을 허가 없이 사용하지 않습니다.
- 사례 콘텐츠에는 별도 동의를 받고 필요한 경우 완전히 익명화합니다.
- 강사는 개인 계정의 비밀번호나 복구 수단을 보관하지 않습니다.

## AI에 자료를 제공하기 전

- [ ] 이 자료의 소유자와 이용 권한을 알고 있다.
- [ ] 다른 사람의 개인정보가 제거되었다.
- [ ] 서비스 제공자에게 전송해도 되는 자료다.
- [ ] 필요한 부분만 최소한으로 제공한다.
- [ ] 프로젝트 폴더 밖의 파일 접근이 필요하지 않다.
- [ ] 삭제·결제·외부 전송 작업은 별도 승인을 요구한다.

## 에이전트 실행 전

- [ ] 현재 작업 폴더가 맞다.
- [ ] 변경 가능한 파일 범위가 정해져 있다.
- [ ] 실행할 명령과 예상 영향이 설명되어 있다.
- [ ] 중요한 원본 파일의 복사본이나 Git 이력이 있다.
- [ ] 외부 업로드, 메시지 전송, 배포는 자동 승인하지 않는다.
- [ ] 비용이 발생하는 작업의 한도를 정했다.

## GitHub 공개 전

- [ ] 저장소 전체에서 비밀번호·토큰·개인정보를 확인했다.
- [ ] `.env`, 키 파일, 개인 설정 파일이 제외되어 있다.
- [ ] 현재 파일뿐 아니라 이전 커밋에도 비밀정보가 없는지 확인했다.
- [ ] 이미지의 얼굴, 알림, 경로, 계정명이 제거되었다.
- [ ] 문서와 데이터의 저작권 및 이용 조건을 확인했다.
- [ ] 결과물의 오류, 한계, AI 사용 여부를 필요한 범위에서 설명했다.
- [ ] 공개 저장소가 정말 필요한지 다시 확인했다.

비밀정보가 한 번이라도 커밋되었다면 파일을 삭제하는 것만으로 해결되지 않을 수 있습니다. 즉시 강사에게 알리고 해당 키나 토큰을 폐기·재발급한 뒤 기록 정리 방법을 확인합니다.

## 공개 수준

| 수준 | 대상 | 예시 |
|---|---|---|
| 개인 | 참가자만 접근 | 초기 작업, 개인 회고 |
| 수업 | 참가자와 강사만 접근 | 피드백용 결과물 |
| 제한 공유 | 지정한 가족·동료 | 재현성 시험 |
| 공개 | 누구나 접근 | 검토를 마친 README와 결과물 |

## 사례 콘텐츠 사용 동의 항목

사례를 콘텐츠로 사용하기 전에 다음을 별도로 정합니다.

- 공개할 이름 또는 익명 표기
- 공개할 문제와 결과물 범위
- 화면, 음성, 사진 사용 여부
- 수치와 전후 비교의 정확성
- AI 대화와 원본 파일 공개 여부
- 게시 채널과 사용 기간
- 수정 또는 철회 요청 방법
