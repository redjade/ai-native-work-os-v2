# 대상별 프로젝트 예시

> **무엇을** 같은 산출물 루프를 중학생·고등학생·대학생·대학원생·직장인이 각각 어떤 프로젝트로 쓰는지 보여 줍니다.
> **왜** "나 같은 사람은 이걸로 뭘 만들지?"가 막연할 때, 자기와 가까운 예시가 있으면 시작하기 쉽습니다.
> **나에게 무슨 의미** 자기 상황에 맞는 4주 프로젝트를 고르는 출발점이 됩니다.

모든 예시는 같은 여섯 단계(정의 → 위임 → 검증 → 기록 → 공유 → 개선)를 씁니다. 대상이 달라도 방법은 같고, **소재와 결과물의 형태만 다릅니다.**

각 예시는 [좋은 범위](00-course-guide.md) 기준을 지킵니다 — 4주 안에 작은 완성본이 나오고, 검증할 방법이 있고, 민감정보 없이 가능한 것.

## 중학생

| 항목 | 내용 |
|---|---|
| 문제 | 과학 수행평가 주제를 정하고 자료를 모으는 게 막막하다 |
| 결과물 | 주제 하나에 대한 출처 5개 카드 + 한 장 정리 노트 |
| 위임 | "이 자료에서 사실과 의견을 나눠서 표로 보여 줘" |
| 검증 | 각 사실이 원문에 실제로 있는지 직접 확인 |
| 공유 | 부모님·친구에게 노트를 보여 주고 이해되는지 확인 |
| 안전 | 학교 자료·친구 정보는 넣지 않기 |

시작이 어렵다면: 좋아하는 주제(게임·스포츠·음식) 하나로 출처 3개 정리부터.

## 고등학생

| 항목 | 내용 |
|---|---|
| 문제 | 오답이 반복되는데 뭘 복습해야 할지 정리가 안 된다 |
| 결과물 | 오답 기록에서 다음 복습 문제 5개를 뽑아 주는 흐름 |
| 위임 | "이 오답들의 공통 유형을 찾고, 비슷한 연습 문제를 만들어 줘" |
| 검증 | 만든 문제의 답이 실제로 맞는지 직접 풀어 확인 |
| 공유 | 같은 과목 친구와 문제·풀이 노트를 교환 |
| 안전 | 시험지 원본·성적은 공개하지 않기 |

주의: AI가 만든 문제의 정답은 반드시 사람이 검증합니다. 특히 수학·과학은 틀린 답을 자신 있게 제시할 수 있습니다.

## 대학생

| 항목 | 내용 |
|---|---|
| 문제 | 팀플·리포트에서 자료 조사와 인용 정리에 시간이 너무 든다 |
| 결과물 | 주제 관련 출처 10개의 주장-근거표 + 인용 목록 |
| 위임 | "이 자료들의 핵심 주장을 표로 정리하고, 인용 위치를 표시해 줘" |
| 검증 | DOI·저자·연도가 실제로 존재하는지 확인 (지어낸 인용 걸러내기) |
| 공유 | 팀원이 README만 보고 표를 이해·재사용할 수 있는지 확인 |
| 안전 | 교수·동료의 미공개 자료는 허가 전 사용 금지 |

이 대상은 [워크드 예시: 여러 논문 정리](10-worked-example-papers.md)를 그대로 따라 하기 좋습니다.

## 대학원생

| 항목 | 내용 |
|---|---|
| 문제 | 문헌이 수십 편인데 무엇이 합의·논쟁·공백인지 지도가 없다 |
| 결과물 | 논문 15편의 주장-근거 연결표 + 미해결 질문 목록 + 검토 가능한 개요 |
| 위임 | "노트를 근거로 합의점·상충점·연구 공백을 분리해 줘" |
| 검증 | 각 주장을 원문 페이지와 대조, 인용 검증 기록 남기기 |
| 공유 | 지도교수·동료에게 개요를 보여 주고 빠진 관점 확인 |
| 안전 | 미공개 데이터·연구윤리 승인 범위 확인 |

이 대상은 [다음 단계](09-next-steps.md)의 평가·트레이스 개념으로 자연스럽게 이어집니다.

## 직장인 (비개발 직군)

| 항목 | 내용 |
|---|---|
| 문제 | 매주 반복되는 정리·보고 작업에 시간이 든다 |
| 결과물 | 한 가지 반복 업무를 처리하는 작은 자동화 또는 표준 템플릿 |
| 위임 | "이 입력에서 이런 형식의 요약을 만들어 줘. 예시 하나로 먼저 보여 줘" |
| 검증 | 예시 입력·잘못된 입력·수작업 결과와 비교 |
| 공유 | 동료가 절차서만 보고 같은 결과를 낼 수 있는지 확인 |
| 안전 | 고객 정보·사내 비공개 자료는 넣지 않기, 정보 등급 먼저 분류 |

주의: 회사 자료를 다룰 때는 [정보 분류](01-preflight.md)를 먼저 확인하고, 허용된 자료만 사용합니다.

## 공통으로 피할 것

대상과 무관하게 다음은 4주 프로젝트에 맞지 않습니다.

- 검증할 방법이 없는 결과물 (맞는지 확인 못 하는 것)
- 민감정보가 반드시 필요한 프로젝트
- 4주 안에 작은 완성본조차 안 나오는 큰 범위
- 남의 자료를 허가 없이 써야 하는 것
