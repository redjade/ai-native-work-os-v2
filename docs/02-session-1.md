# 1주차: 문제 정의와 첫 결과물

## 이번 주 목표

모호한 아이디어를 4주 프로젝트로 줄이고, 수업 안에 첫 번째 작은 결과물을 만듭니다.

## 수업 전 준비

- [ ] [사전 준비 체크리스트](01-preflight.md)를 완료했다.
- [ ] 프로젝트 후보를 두 개 적었다.
- [ ] 공개하면 안 되는 자료를 구분했다.
- [ ] 개인 작업 폴더를 준비했다.

## 수업에서 배우는 것

- 문제와 해결책을 구분하는 법
- 산출물과 활동을 구분하는 법
- 완료 조건을 관찰 가능한 문장으로 쓰는 법
- 큰 프로젝트를 30~90분 작업으로 줄이는 법
- AI에게 파일을 보여 주기 전 확인할 사항

## 실습 1: 프로젝트 한 문장

다음 형식으로 작성합니다.

```text
[사용자]가 [상황]에서 겪는 [구체적인 문제]를 줄이기 위해
[형식이 분명한 결과물]을 만든다.
```

예시:

```text
논문 초안을 준비하는 대학원생이 출처와 주장을 혼동하는 문제를 줄이기 위해
출처 15개의 핵심 주장과 인용 위치를 확인할 수 있는 근거표를 만든다.
```

## 실습 2: 완료 조건

“좋다”, “유용하다”, “잘 된다” 대신 관찰 가능한 조건을 사용합니다.

- [ ] 결과물의 파일 또는 링크가 존재한다.
- [ ] 예시 입력으로 실행하거나 읽어 볼 수 있다.
- [ ] 예상 결과와 실제 결과를 비교할 수 있다.
- [ ] 다른 사람이 설명서를 보고 핵심 기능을 확인할 수 있다.
- [ ] 민감정보가 포함되지 않는다.

## 실습 3: 프로젝트 작업공간

[프로젝트 정의서](../templates/project-brief.md)를 복사해 `PROJECT.md`로 저장합니다.

최소 구조:

```text
project-name/
  PROJECT.md
  TASKS.md
  LOG.md
  README.md
  output/
```

## 실습 4: 첫 번째 작은 결과물

첫 결과물은 30분 안에 만들어야 합니다.

예시:

- 연구: 출처 3개의 비교표
- 지식관리: 노트 3개와 인덱스 1개
- 제작: 고정된 예시 입력 하나를 처리하는 화면 또는 스크립트

완성도가 낮아도 열어 보거나 실행할 수 있어야 합니다.

## 수업 종료 체크리스트

- [ ] 프로젝트 문제를 한 문장으로 설명할 수 있다.
- [ ] 4주 최종 결과물의 형태가 정해졌다.
- [ ] 하지 않을 일이 적혀 있다.
- [ ] 완료 조건이 세 개 이상 있다.
- [ ] 첫 번째 작은 결과물이 존재한다.
- [ ] 결과물의 한계나 오류를 하나 이상 기록했다.
- [ ] 오늘 작업을 Git 또는 작업 로그에 남겼다.
- [ ] 다음 작업 하나가 정해졌다.

## 숙제

1. 첫 결과물을 한 번 개선합니다.
2. AI 사용 전과 사용 후에 걸린 시간을 기록합니다.
3. [주간 회고](../templates/weekly-review.md)를 작성합니다.
4. 다음 질문에 한 문장씩 답합니다.

```text
무엇을 만들었는가?
무엇을 배웠는가?
무엇을 기록했는가?
다음에는 무엇을 개선할 것인가?
```

## 제출물

- `PROJECT.md`
- 첫 결과물
- 작업 로그 또는 커밋 링크
- 주간 회고
