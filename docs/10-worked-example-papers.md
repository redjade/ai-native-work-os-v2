# 워크드 예시: 여러 논문 관리·번역·정리

> **무엇을** 논문 여러 편을 모아 정리하고, 번역하고, 비교표까지 만드는 전체 과정을 처음부터 끝까지 따라 합니다.
> **왜** "논문을 AI로 정리한다"는 막연한 목표를 실제로 어떤 파일과 단계로 하는지 보여 주기 위해서입니다.
> **나에게 무슨 의미** 연구·학습에서 자료가 여러 개일 때 흩어지지 않고 관리하는 방법을 그대로 가져다 쓸 수 있습니다.

이 예시는 [연구 트랙](00-course-guide.md)의 구체적 사례입니다. 논문 대신 기사·판례·리포트·교과서 단원으로 바꿔도 같은 방법이 적용됩니다.

## 상황

세 편의 논문을 읽고 "이 주제에서 무엇이 합의되어 있고 무엇이 다른가"를 정리해야 합니다. 언어는 영어이고, 시간은 제한적입니다.

흔한 실패:

- 세 PDF를 AI에 한꺼번에 던지고 "요약해 줘"라고 함 → 출처가 섞이고 어느 논문 이야기인지 알 수 없음
- 번역만 잔뜩 저장 → 나중에 원문과 대조할 수 없음
- 채팅에만 남음 → 다음 주에 사라짐

## 폴더 구조

```text
projects/
  literature-review/
    PROJECT.md
    knowledge/
      sources/
        2021-kim-attention-in-ux.md
        2022-lee-agent-eval.md
        2023-park-human-ai-team.md
      concepts/
        claim-comparison.md
      questions/
        open-questions.md
    outputs/
      comparison-table.md
    logs/
      LOG.md
```

**파일 이름 규칙:** `연도-저자-짧은주제`. 이렇게 하면 목록만 봐도 무엇인지 알 수 있고 정렬됩니다.

## 단계별 진행

### 1단계 — 논문 하나에 노트 하나

논문 한 편당 `sources/` 노트 하나를 만듭니다. **한 번에 한 편만** 다룹니다. 여러 편을 섞지 않는 것이 핵심입니다.

각 노트는 [지식 노트 템플릿](../templates/knowledge-note.md)을 사용합니다.

AI에는 이렇게 요청합니다:

```text
이 논문(2021-kim-attention-in-ux) 하나만 봐 주세요. 아직 파일은 수정하지 마세요.
다음을 표로 보여 주세요.
1. 연구 질문
2. 방법
3. 핵심 결론 (각 결론에 논문 내 위치를 표시)
4. 저자가 인정한 한계
원문에 없는 내용은 추가하지 말고, 불확실하면 '불명확'으로 표시하세요.
```

받은 표를 그대로 저장하지 않고, 원문과 대조해 맞는 것만 노트에 옮깁니다.

### 2단계 — 번역은 원문과 나란히

번역이 필요하면 **원문을 지우지 않습니다.** 원문과 번역을 나란히 둡니다.

```text
## 핵심 주장 (원문 / 번역)

- 원문: "Attention cues reduced task-switching cost by 18%." (p.7)
- 번역: 주의 유도 신호가 작업 전환 비용을 18% 줄였다. (p.7)
- 내 확인: 표 3에서 수치 확인함. 통계적 유의성은 p.8.
```

번역은 이해를 돕는 보조이고, 검증의 기준은 항상 원문입니다.

### 3단계 — 세 노트가 생긴 뒤에 비교

세 편의 `sources/` 노트가 각각 완성된 **뒤에** 비교를 시작합니다. 이때는 노트를 근거로 삼습니다.

```text
sources/ 폴더의 세 노트만 근거로, 아래 표를 만들어 주세요.
행: 연구 질문 / 방법 / 핵심 결론 / 합의되는 점 / 서로 다른 점
열: 세 논문
각 칸에는 근거가 된 노트 파일명을 표시하세요. 노트에 없는 내용은 추가하지 마세요.
```

결과는 `outputs/comparison-table.md`에 저장합니다.

### 4단계 — 다른 점과 질문 분리

논문들이 서로 어긋나는 지점은 `concepts/claim-comparison.md`에, 아직 확인 못한 것은 `questions/open-questions.md`에 적습니다. 이 둘을 섞지 않습니다.

### 5단계 — 커밋

각 단계가 끝날 때마다 설명 있는 커밋을 남깁니다.

```text
docs: add source note for kim 2021
docs: add source note for lee 2022
docs: add three-paper comparison table
```

이렇게 하면 나중에 "언제 어느 논문을 정리했는지"를 커밋 기록으로 되짚을 수 있습니다.

## 검증 체크리스트

- [ ] 각 결론에 논문 내 위치(페이지·표)가 적혀 있다.
- [ ] 번역 옆에 원문이 남아 있다.
- [ ] 비교표의 각 칸이 어느 노트에서 왔는지 알 수 있다.
- [ ] AI가 지어낸 인용이나 수치가 없다. (원문에서 실제로 확인함)
- [ ] 합의된 점과 다른 점이 구분되어 있다.
- [ ] 아직 확인 못한 질문이 따로 적혀 있다.

## 왜 이렇게 하나

- **한 번에 한 편**: 출처가 섞이는 가장 흔한 실패를 막습니다.
- **원문 보존**: 번역·요약을 나중에 검증할 수 있습니다.
- **노트를 근거로 비교**: AI가 원문을 다시 지어내지 않고, 사람이 확인한 노트만 사용합니다.
- **단계별 커밋**: 과정이 눈에 보이고 안전하게 남습니다.
