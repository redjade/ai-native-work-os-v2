# AI Native Work OS

AI를 이용해 **내 문제를 작게 정의하고, 결과물을 만들고, 검증하고, 기록하고, 안전하게 공유하는 방법**을 익히는 4주 프로젝트 프로그램입니다.

이 과정의 목표는 AI 도구를 많이 아는 것이 아닙니다. 과정이 끝난 뒤에도 혼자 반복할 수 있는 작업 습관과 작업공간을 만드는 것이 목표입니다.

> 정의 → 위임 → 검증 → 기록 → 공유 → 개선

이 여섯 단계를 이 과정에서는 **산출물 루프**라고 부릅니다.

## 4주 뒤에 남는 것

참가자는 과정이 끝날 때 다음을 갖게 됩니다.

- 실제로 열어 보거나 실행할 수 있는 프로젝트 결과물 1개
- 목표, 제약조건, 완료 기준이 적힌 프로젝트 정의서
- AI에게 일을 맡길 때 재사용할 작업 지시서
- 결과가 맞는지 확인한 검증 기록
- 변경과 판단을 남기는 Git·작업 로그
- 다른 사람이 이해할 수 있는 README 또는 설명서
- 개인정보와 비밀정보를 제외한 안전한 공유본
- 다음 30일 동안 실행할 개선 계획

## 대상

- AI를 채팅 외의 실제 작업에 활용하고 싶은 사람
- 논문, 조사, 지식관리, 자동화 또는 작은 프로그램을 만들고 싶은 사람
- 코딩 경험은 적지만 자신의 문제를 직접 해결해 보고 싶은 사람
- 중학생 이상 참가자와 가족

코딩 경험은 필수가 아닙니다. 다만 개인 노트북으로 파일과 폴더를 만들고 웹사이트에 로그인할 수 있어야 합니다.

## 이 과정에서 하지 않는 것

- 특정 진로나 직업을 정해 주지 않습니다.
- 정서 상담, 생활 통제 또는 성적 관리를 제공하지 않습니다.
- AI가 만든 결과를 정답으로 보증하지 않습니다.
- 참가자의 계정 비밀번호나 API 키를 대신 보관하지 않습니다.
- 도구 기능을 많이 외우거나 경쟁적으로 산출물 수를 늘리지 않습니다.

성과는 **결과물과 검증 근거**를 중심으로 확인합니다.

## 운영 방식

- 오프라인 4회, 회당 2시간
- 정규 과정 전 사전 준비 및 환경 점검
- 참가자마다 프로젝트 1개 선택
- 매주 작동하는 작은 결과물을 제출
- 수업 시간에는 설명보다 직접 만드는 시간을 더 많이 사용
- 마지막 주에 결과물 시연과 30일 계획 작성

## 주차별 과정

| 단계 | 주제 | 핵심 결과물 |
|---|---|---|
| 사전 준비 | 장비·계정·도구·보안 점검 | 준비 체크리스트와 기초 진단 |
| 1주차 | 문제 정의, LLM Wiki와 Git 작업 | `PROJECT.md`, 지식 인덱스와 첫 산출물 |

| 4주차 | 안전한 공유와 개선 | 최종 시연, 평가표, 30일 계획 |

## 필요한 도구

기본 도구는 다음과 같습니다.

- 개인 노트북과 안정적인 인터넷 연결
- GitHub 계정
- Git
- Obsidian
- Codex 또는 Claude Code 중 주 도구 1개
- 브라우저와 이메일 계정

수업 자료는 Codex와 Claude Code를 모두 지원합니다. 참가자는 계정과 선호에 따라 주 도구를 하나 선택하고, 공통 작업 지시서와 검증 절차를 사용합니다. 같은 과제를 두 도구로 중복 수행할 필요는 없습니다.

## 프로젝트 예시

### 연구·논문

- 연구 질문과 범위 정의
- 출처 목록과 근거표
- 주장-근거 연결표
- 논문 목차 또는 검토 가능한 초안
- 인용과 출처 검증 기록

### 지식관리

- Obsidian 기반 주제별 지식 저장소
- 노트 작성·연결·검토 규칙
- 자료를 다시 찾는 검색 실험
- 주간 리뷰 대시보드

### 제작·자동화

- 작은 웹페이지 또는 계산기
- 반복 파일 작업 자동화
- 개인용 체크리스트 도구
- 데이터 정리 또는 보고서 생성 흐름

프로젝트는 4주 안에 완성할 수 있어야 합니다. “AI 서비스 만들기”보다 “특정 자료를 입력하면 검토 가능한 요약표를 만드는 도구”처럼 결과를 확인할 수 있는 범위가 좋습니다.

## 참가자의 기본 약속

- 비밀번호, API 키, 주민번호, 주소 등 민감정보를 AI나 저장소에 입력하지 않습니다.
- 다른 사람의 자료는 허락 없이 업로드하지 않습니다.
- AI 결과는 출처, 테스트 또는 직접 비교를 통해 확인합니다.
- 공개 여부는 참가자가 선택하며, 수업을 위해 공개 저장소를 만들 필요는 없습니다.
- 실패와 수정도 작업 기록으로 남깁니다.

## 시작하기

처음 참가한다면 다음 순서로 진행합니다.

1. [과정 안내](docs/00-course-guide.md)를 읽고 프로젝트 후보를 정합니다.
2. [사전 준비 체크리스트](docs/01-preflight.md)를 완료합니다.
3. [프로젝트 정의서](templates/project-brief.md)를 복사해 작성합니다.
4. 저장소와 작업 폴더는 기본적으로 비공개로 시작합니다.
5. 첫 수업 전 해결되지 않은 설치 문제를 강사에게 전달합니다.

## 자료 이용

개인 프로젝트에 복사·수정해 사용하는 것은 허용합니다. 전체 자료의 공개 재배포, 재판매 또는 유료 교육 운영에는 별도 허락이 필요합니다. 자세한 내용은 [파일럿 자료 이용 안내](TERMS-OF-USE.md)를 따릅니다.
