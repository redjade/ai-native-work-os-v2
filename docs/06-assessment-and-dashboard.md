# 진단표와 대시보드 운영

## 진단의 목적

진단은 참가자를 서열화하기 위한 것이 아닙니다. 현재 혼자 할 수 있는 단계와 도움이 필요한 단계를 확인하기 위한 도구입니다.

진단은 세 번 실시합니다.

1. 시작 전: 기준점 확인
2. 매주: 다음 행동 선택
3. 4주차: 변화와 30일 계획 확인

## 점수 기준

| 점수 | 의미 |
|---|---|
| 0 | 수행하지 않았거나 근거가 없음 |
| 1 | 강사의 도움을 받아 수행 |
| 2 | 안내서를 참고해 혼자 한 번 수행 |
| 3 | 반복 수행하고 다른 사람에게 설명 가능 |

## 핵심 진단표

| 영역 | 확인 질문 | 점수 | 근거 링크 |
|---|---|---:|---|
| 문제 정의 | 사용자, 문제, 결과물과 완료 조건이 명확한가? | 0~3 |  |
| 작업 분해 | 30~90분 단위로 다음 행동을 정할 수 있는가? | 0~3 |  |
| 위임 | 목표, 맥락, 제약, 완료 조건을 AI에 전달하는가? | 0~3 |  |
| 프롬프트 개선 | 관찰한 실패를 근거로 지시 또는 규칙 한 줄을 수정하고, 같은 기준으로 결과 차이를 설명하는가? | 0~3 |  |
| 결과물 | 실제로 열거나 실행할 수 있는 산출물이 있는가? | 0~3 |  |
| 검증 | 테스트, 출처, 비교 등 외부 증거가 있는가? | 0~3 |  |
| 재현성 | 다른 사람이 설명서만 보고 핵심 결과를 확인하는가? | 0~3 |  |
| 설명 가능성 | 문제, 방법, 결과, 한계를 3분 안에 설명하는가? | 0~3 |  |
| 기록과 개선 | 결정, 실패, 변경을 기록하고 규칙을 갱신하는가? | 0~3 |  |
| 보안 | 정보 등급과 공개 위험을 스스로 판단하는가? | 0~3 |  |

총점: __ / 30

보안은 별도 통과 조건입니다. 총점이 높아도 보안 검토를 통과하지 못하면 결과물을 공개하지 않습니다.

## 주간 성과 지표

### 핵심 지표

- 검증된 주간 결과물 수
- 완료 조건 충족률
- 다른 사람의 재현 성공 여부
- 수정 전후의 품질 개선
- 관찰한 실패를 근거로 다시 검증한 작업 수
- 검증 근거가 연결된 결과물 비율
- 공개 가능한 결과물 수
- 설명 가능성 점수
- 작업 규칙이나 템플릿으로 전환된 반복 문제 수

### 관찰용 지표

- 커밋 수
- AI 작업 세션 수
- 회고 수
- 작업 시간
- AI 비용과 구독 비용
- 막힌 시간
- 강사의 개입 횟수

관찰용 지표는 성과 점수로 직접 사용하지 않습니다. 커밋이나 프롬프트 수가 많다는 사실은 품질을 보장하지 않습니다.

## 주간 대시보드

| 프로젝트 | 이번 주 검증된 결과물 | 상태 | 근거 | 가장 큰 위험 | 다음 행동 | 검토일 |
|---|---|---|---|---|---|---|
|  |  | 초록/노랑/빨강 |  |  |  |  |

상태 기준:

- 초록: 다음 행동과 검증 방법이 명확함
- 노랑: 결과물은 있으나 검증 또는 범위 조정이 필요함
- 빨강: 환경, 정보, 권한 또는 목표 문제로 진행이 중단됨

## 주간 점검 질문

```text
무엇을 만들었는가?
어떤 근거로 작동한다고 판단했는가?
AI가 틀리거나 불확실했던 부분은 무엇인가?
그 관찰을 바탕으로 어떤 지시 또는 규칙 한 줄을 고쳤는가?
다음에도 사용할 수 있도록 무엇을 기록했는가?
시간이나 비용을 줄인 부분은 무엇인가?
새로 생긴 보안 또는 공개 위험은 무엇인가?
다음 주에 개선할 행동 하나는 무엇인가?
```

## 월간 점검 질문

- 지난달에 실제로 사용된 결과물은 무엇인가?
- 사용되지 않은 결과물과 도구는 무엇인가?
- 반복해서 발생한 문제는 무엇인가?
- 어떤 문제를 템플릿, 규칙 또는 자동화로 바꿀 것인가?
- AI 비용과 구독은 얻은 가치에 비해 적절한가?
- 접근 권한과 공개 범위는 여전히 적절한가?
- 다음 달의 가장 작은 검증 가능한 결과물은 무엇인가?
