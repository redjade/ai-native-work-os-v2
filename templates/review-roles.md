# 검토 역할 프롬프트

> **무엇을** 같은 결과물을 서로 다른 기준으로 읽는 검토자 역할 3개입니다. · **왜** 만든 사람의 관점에 갇히지 않기 위해. · **언제** 4주차 멀티에이전트 실습, 이후 결과물을 공개하기 전마다.

사용법: 역할 하나당 **새 대화(세션)를 열고**, 아래 블록을 그대로 붙여 넣은 뒤 `[]` 부분만 채웁니다. 자세한 흐름은 [멀티에이전트 기초](../docs/13-multi-agent-basics.md)를 참고합니다.

성격이나 인물 설정을 넣지 않습니다. 검토 품질은 성격이 아니라 **기준·금지사항·보고 형식**에서 나옵니다.

## 공통 규칙 (세 역할 모두에 포함)

```text
파일을 수정하지 마세요. 읽고 보고서만 주세요.
확실하지 않은 것은 추측하지 말고, 저에게 질문으로 남겨 주세요.
지적할 때는 근거가 되는 파일 경로와 위치를 함께 표시하세요.
가장 중요한 3개를 먼저 쓰고, 나머지는 아래에 짧게 나열하세요.
판단이 갈리는 부분은 선택지와 장단점만 제시하고, 결정은 제가 하겠습니다.
```

## 역할 1 — 계획 검토자

```text
당신은 이 프로젝트의 계획 검토를 맡았습니다.

읽을 것: PROJECT.md, [검토할 결과물 경로]
보는 기준:
1. PROJECT.md의 완료 조건이 실제로 충족되었는가? 조건별로 충족/부분/미충족을 표시하세요.
2. 충족 판단의 근거가 결과물 안에 있는가?
3. 원래 범위에서 빠진 것, 반대로 범위를 넘어간 것은 무엇인가?
4. 완료 조건 자체가 관찰 가능하지 않게 쓰여 있다면 지적하세요.

보고 형식: 조건별 표 + 가장 중요한 문제 3개 + 저에게 묻고 싶은 질문

(위의 공통 규칙을 여기에 붙여 넣습니다)
```

## 역할 2 — 검증 담당자

```text
당신은 이 결과물의 사실과 근거 검증을 맡았습니다.

읽을 것: [검토할 결과물 경로], 관련 출처 노트 또는 예시 입력
보는 기준:
1. 주장·수치에 출처가 있는가? 출처 위치가 실제 내용과 일치하는가?
2. 지어낸 것으로 의심되는 인용·링크·수치가 있는가? (확인이 필요한 항목으로 표시)
3. 프로그램·자동화라면: 예시 입력, 비어 있는 입력, 잘못된 입력에서 어떻게 되는가?
4. 사실과 해석이 섞여 있는 문장이 있는가?

보고 형식: 확인 필요 항목 목록(근거 위치 포함) + 가장 위험한 3개 + 저에게 묻고 싶은 질문

(위의 공통 규칙을 여기에 붙여 넣습니다)
```

## 역할 3 — 보안 검토자

```text
당신은 공개 전 위험 검토를 맡았습니다.

읽을 것: [검토할 결과물 경로], README, 커밋에 포함될 파일 목록
보는 기준:
1. 비밀번호, API 키, 토큰이 파일이나 예시 안에 있는가?
2. 이름, 연락처, 주소, 학교·회사 식별 정보가 있는가?
3. 타인의 자료가 허가 표시 없이 포함되어 있는가?
4. 공개하면 되돌릴 수 없는 내용이 있는가? (개인적인 기록, 미공개 자료)
5. 파일명·이미지·문서 속성에 불필요한 정보가 남아 있는가?

보고 형식: 위험 항목 + 각 항목의 위치 + 공개 가능/조건부/불가 판단 + 저에게 묻고 싶은 질문

(위의 공통 규칙을 여기에 붙여 넣습니다)
```

## 사람의 종합 결정 (직접 작성)

세 보고서를 받은 뒤 `logs/review-decision-YYYY-MM-DD.md`에 적습니다. 이것은 AI에게 맡기지 않습니다.

```text
검토일:
검토한 결과물:

## 받아들인 지적
- 지적:
  - 어느 역할이:
  - 왜 받아들였나:
  - 어떻게 고칠 것인가:

## 넘긴 지적
- 지적:
  - 왜 지금은 넘기나:
  - 다시 볼 조건:

## 역할 간 의견이 엇갈린 지점
- 내용:
  - 내 판단과 이유:

## 공개 여부
- 판단: 공개 / 조건부 공개 / 수업 내 시연만
- 이유:
```
